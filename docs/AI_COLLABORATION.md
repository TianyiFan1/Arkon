# AI 协作记录

## AI 使用复盘

先阅读任务文档，再静态检查现有代码。在获得修复授权后，修复 SQLite 技术选型、保存失败跳步、旧评估未失效、缺少事务、套餐金额遗漏和测试隔离问题。

- **数据库建模：** AI 协助把匿名会话、分步答题、健康评估和订阅状态拆分为 `UserSession`、`QuizResponse`、`HealthAssessment`、`Subscription` 四张一对一关联表，并生成 PostgreSQL 迁移。这样进度恢复、计算结果持久化和订阅鉴权都能通过同一个 `sessionId` 关联。
- **Mock / 演示数据：** AI 协助编写幂等 seed 脚本，生成一个已支付和一个未支付会话。seed 调用正式的保存、计算和支付服务，而不是手写结果 JSON，因此演示曲线和营养数据始终与健康算法一致。
- **复杂逻辑：** AI 协助实现版本号冲突处理、会话行锁事务、答案变化后旧评估失效、服务端 BMI / 热量 / 预测日期计算，以及按订阅状态脱敏结果字段。
- **测试与边界：** AI 协助生成算法回归、PostgreSQL 集成、Route Handler 和 Playwright 测试。覆盖缺失/非法年龄身高体重、目标体重关系、危险 BMI、无有效热量缺口、乱序或重复提交、并发更新、未付费字段脱敏，以及 `/pay` 后从预览变为完整结果的流程。

所有 AI 生成内容均以实际代码、迁移、测试报告和线上接口响应复核；AI 负责加快候选方案和测试样例的产出，人负责判断业务规则与验证结果。

## 本轮否决的既有方案

原算法在推荐摄入量触及下限时，使用 `Math.max(150, TDEE - 下限)` 强制生成热量缺口，再用至少 200 的缺口计算日期。原测试只断言摄入量达到下限，无法发现 TDEE 低于摄入量却仍预测减重的问题。

本轮否决该计算与测试思路：热量差改为实际差值，没有正缺口则返回明确错误；新增“不应凭空生成减重日期”和“小于 200 的实际缺口不能被放大”回归测试。判断依据是输出内部的算术一致性，不是将测试改到通过为止。

## 文档事实边界

之前文档中关于“AI 曾提出 CSS 遮罩方案”等历史对话叙述，本轮没有原始记录可核实，已移除，不将其作为真实协作证据。现有服务端脱敏实现得到保留。

测试运行结果以本轮命令和生成报告为准；本地测试通过不等于 GitHub Actions 已通过，也不等于公网部署已验收。后续面试复盘应补充作者实际参与的决策与原始证据。
